# Migrating to v3

This page describes how to migrate from `just-task` v1 / `just-scripts` v2 to v3. (The versions have been updated to match for clarity.)

## General changes

### Minimum Node.js version

The minimum Node.js version is **22.18.0**. This allows direct loading of TypeScript config files.

### Config files

Just now loads config files with native `import()`, supporting TypeScript, ES modules, and top-level `await`. CommonJS configs and existing task registration styles remain supported. The explicit `--esm` option has been removed. (Config discovery now includes `just.config.m[jt]s`.)

For [TypeScript Just configs](../tasks/index.md#defining-tasks-in-style-with-typescript) (`just.config.[cm]?ts`), all support for `ts-node` has been removed. TypeScript files are run directly with Node.js, meaning standard [type stripping restrictions](https://nodejs.org/docs/latest-v22.x/api/typescript.html#type-stripping) apply. Notably, if the file doesn't have an explicit `.cts` or `.mts` extension, its module format is inferred from the nearest `package.json`'s `"type"` field (defaults to `"commonjs"`). As a result, you may need to rename `just.config.ts` to `just.config.mts` to continue using `import` syntax.

(If `ts-node` support removal proves too disruptive, please open an issue to discuss your use case.)

### TypeScript configuration

Due to internal changes, the TypeScript config used for your Just config files (`just.config.ts` etc) may need to be updated:

- `just-task` and `just-scripts` now compile with `esModuleInterop`, which means it may also need to be enabled for your build scripts.
- `just-scripts` references `nano-spawn` types, which use `package.json` `exports`. If TypeScript cannot resolve these declarations, replace legacy `moduleResolution: "node"` with an exports-aware setting, such as `module: "nodenext", moduleResolution: "nodenext"`.
- For running TypeScript directly in Node.js, see [Node's recommended compiler options](https://nodejs.org/docs/latest-v22.x/api/typescript.html#type-stripping). These align type-checking with Node's runtime behavior; Node itself does not read `tsconfig.json`.

## Changes to `just-task`

These changes also apply to APIs re-exported by `just-scripts`.

### `TaskFunction` corrections

The `TaskFunction` types have been corrected to reflect valid usage. For asynchronous work, return a promise or use the `done` callback. For synchronous work, return nothing. Do not accidentally return an unrelated value.

Also, the `TaskContext` type and `TaskFunction`'s `this: TaskContext` have been removed, since tasks were not actually receiving this context at runtime. Import `argv` and `logger` directly instead of accessing `this.argv` or `this.logger`.

### `task()` corrections

The `task()` types now match the argument combinations already supported at runtime. Invalid calls such as `task(fn)` or `task(name, fn, fn)`, which previously passed type-checking but failed at runtime, are now rejected by TypeScript.

Separately, `task(name)` now throws if the task is not registered, instead of returning `undefined`.

Higher order tasks that return another task function are still supported; see [Higher order task functions](../tasks/thunk).

### `resolve` and `resolveCwd`

The second argument to `resolve` and `resolveCwd` must now be an options object, not a directory string.

`resolve` now accepts a `dirname` option to include a custom location (such as the calling package's location) in its search paths.

### Removed cache APIs

`clearCache()` and `TaskFunction.cached` have been removed: the underlying task cache implementation was removed years ago, so these were already no-ops.

## Changes to `just-scripts`

### Explicit optional peer dependencies

All dependencies used by tasks and overlays are explicitly declared as `peerDependencies` with `peerDependenciesMeta[*].optional: true`.

The allowed version ranges are best guesses; only the versions specified as local `devDependencies` in the `just` repo are tested. If you find that an allowed version doesn't work (or a new version is missing), please open an issue or PR to either fix support for that version, or correct the range.

### Dependency and config file resolution

All tasks now **fail if required dependencies are missing**, instead of warning and silently skipping work. All dependencies are resolved and loaded when used, not at task registration time.

Loader paths in `tsOverlay`, `fileOverlay`, `stylesOverlay`, and `createStylesOverlay` now respect Just's dependency resolution locations; missing required loaders throw rather than failing later in webpack. Optional dependencies in `htmlOverlay`, `tsOverlay`, `stylesOverlay`, and `createStylesOverlay` remain optional.

Config resolution in `esbuildTask`, `prettierTask`, `prettierCheckTask`, `createTarTask`, `extractTarTask`, `tscTask`, `tscWatchTask`, and `webpackCliTask` now happens when the task runs, rather than when its factory is called. Tasks which treated a missing config file as a skip condition continue to do so.

### Use object-style task options

Positional-argument signatures have been removed from all tasks, including `cleanTask`, `copyTask`, `sassTask`, and the API Extractor tasks. Use the object param signatures instead.

### Copy tasks and instructions

#### Copy instead of symlink by default

`copyInstructionsTask` and the `copyInstructions` helpers now **copy files by default**. To preserve the previous default of creating symlinks, explicitly set `symlink: true`.

For hand-written `CopyInstruction` objects, replace `noSymlink` with `symlink` and invert its value. For merged files, leave `symlink` unset or set it to `false`.

#### Use object-style parameters

All copy-instruction helpers now take a single object parameter, not positional arguments.

#### Glob handling changes

`copyTask` now uses `glob` v14 instead of v7 (see the [glob changelog](https://github.com/isaacs/node-glob/blob/main/changelog.md)). Glob patterns **must use forward slashes**, including on Windows; do not use `path.join()` to construct glob patterns.

`copyTask` now correctly determines the destination layout for patterns with glob magic inside a path segment. For example, `src/assets-*/image.png` now copies relative to `src`, preserving the matched `assets-*` directory under the destination. Check output paths if you use these patterns.

### Webpack

Use **`webpack` v5**, **`webpack-cli` v5 or newer** for CLI tasks, and **`webpack-dev-server` v4 or newer** for the dev server. These ranges are intentionally permissive; choose versions that satisfy each other's peer dependencies. For example, `webpack-cli` v7 requires newer webpack v5 releases and `webpack-dev-server` v5 or newer.

For native TypeScript config loading, **`webpack-cli` v7 is recommended**: it uses native `import()` without trying to register `ts-node`. With v5/v6, pass `webpackCliArgs: ['--disable-interpret']` to skip legacy TypeScript-loader registration and let Node load TypeScript directly. Older CLI releases may also need an explicit `--config` path and have limitations around ESM and top-level `await`; upgrade to v7 if these affect your config.

`webpackTask` also uses native `import()` to load config files.

`webpackDevServerTask` now runs `webpack serve`, so it needs `webpack-cli` as well as `webpack` and `webpack-dev-server`.

Due to removal of `ts-node` support, the `transpileOnly` and `tsconfig` options have been removed from `webpackTask`, `webpackCliTask`, and `webpackDevServerTask`. This means the [native TypeScript restrictions](#config-files) described above apply to webpack configs too.

#### CSS modules

The default `stylesOverlay`, including the one used by `webpackConfig` and `webpackServeConfig`, no longer treats every stylesheet as a CSS module. `createStylesOverlay` now consistently honors its `modules` option:

- **Omitted**: Enable CSS modules only for `.module.css`, `.module.scss`, and `.module.sass` files
- `true`: Enable CSS modules for all matched stylesheets
- `false`: Disable CSS modules for all matched stylesheets

If your imports rely on generated class names from files such as `styles.scss`, rename them to `styles.module.scss` and update their imports. Alternatively, explicitly use `createStylesOverlay({ modules: true })` in place of `stylesOverlay()` in your overlay composition to preserve the previous all-modules behavior. Setting `localIdentName` alone no longer enables modules for every file.

Check both your stylesheet imports and the rendered application after upgrading, since this can change class names without failing the build.

#### Task and overlay options

- Remove `WebpackTaskOptions.env`, since it wasn't used at runtime. (The `env` option on `webpackCliTask` and `webpackDevServerTask` is still supported for child-process environment variables.)
- `WebpackTaskOptions.onCompile` now types `stats` as `Stats | MultiStats | undefined`.
- The `checkerOptions` option now uses the installed `fork-ts-checker-webpack-plugin`'s `TsCheckerOptions` type.
- `htmlOverlay` options now use `html-webpack-plugin`'s option type instead of `any`.

### ESLint, Jest, and Prettier

Config discovery now recognizes ESLint flat configs and additional Jest config extensions. `eslintTask` has a `useFlatConfig` option to opt in on ESLint v8 or opt out on v9; it is not needed for the default mode.

`taskPresets.lib()` and `taskPresets.webapp()` now register `eslint` instead of `tslint`. The library preset's `lint` task now runs ESLint.

Prettier and other CLI tasks now resolve binaries from package metadata rather than relying on a fixed internal file path. Continue to pass your own `configPath` or `ignorePath` when needed.

### Sass

`sassTask` uses Sass's modern `compile()` API when available, falling back to the legacy `render()` API for implementations such as `node-sass`. Prefer the maintained `sass` package. Verify generated CSS and any Sass imports when changing implementations.

Custom `postcssPlugins` are now typed as PostCSS `AcceptedPlugin[]`.

### API Extractor

The `fixNewlines` task option was removed. If you want platform-native newlines, set `"newlineKind": "os"` in `api-extractor.json` instead.

`ApiExtractorOptions.onResult` now receives API Extractor's `ExtractorResult` and `IExtractorInvokeOptions` types rather than `any`.

### Process execution

`nodeExecTask` and tasks that launch tool CLIs now use `nano-spawn` rather than the previous spawning implementation.

- TypeScript files are now run natively, so `nodeExecTask`'s `enableTypeScript`, `tsconfig`, and `transpileOnly` options have been removed.
- `nodeExecTask`'s `spawnOptions` uses `nano-spawn`'s options type.
- `nodeExecTask`'s `env` option is now **merged with `process.env`**.
- CLI failures now reject with `nano-spawn`'s `SubprocessError`.

The deprecated `spawn` and `encodeArgs` functions have been removed. Neither one properly handled security concerns, quoting, or other issues, so it's better to use a more mature purpose-specific library instead (such as `shell-quote` for escaping, or `execa` or `nano-spawn` for process spawning).

### Tar tasks

`createTarTask` and `extractTarTask` now propagate read, archive, and write failures correctly.

The task option and entry-header types have been corrected to match `tar-fs`'s runtime behavior:

- The create task's `filter` receives only the path, not an entry header.
- The extract task's `filter` receives an optional header.
- Remove `dereference` from extraction options. It remains supported for creation.
- `EntryHeader` types have been updated.
